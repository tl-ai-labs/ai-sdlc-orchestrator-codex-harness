# Troubleshooting

> **For:** hitting an error and needing symptom → cause → fix. **Also see:** [../SETUP.md](../SETUP.md) · [running.md](running.md) · [architecture.md](architecture.md)

Symptom → cause → fix. Where the fix is a command, it is copy-paste-runnable.

## How to inspect what is happening

| Command | What it tells you |
|---|---|
| `node plugin/codex/verify-setup.mjs` | Full offline check. Reports blocking (`✗`) and warning (`!`) findings, each with the fix. The first thing to reach for. |
| `node plugin/codex/verify-setup.mjs --fix` | The same, then repairs what can be repaired without asking — installs and builds the bridge, links skills onto codex's scan path. |
| `$mmo-codex:setup` | The same check from inside a codex session, pausing only when a human decision is genuinely needed. |
| `$mmo-codex:policy` | Which policy this project uses. `$mmo-codex:policy change` swaps it. |
| `node plugin/scripts/setup-policy.mjs --check-creds --policy=<name>` | Whether this machine has what a specific policy needs, as JSON. A `routing-policy.yaml` at the project root is checked instead. With a built bridge, only the select-slot options the run uses count. |
| `node plugin/codex/run.mjs --dry-run --brief=<path> --mode=greenfield --gates=auto-approve` | Prints the resolved policy, the pin, the run folder and the exact `codex exec` argv, then exits without spending. |
| `codex plugin list` | Whether the plugin is installed and enabled, and which directory it resolves to. |
| `node plugin/scripts/probe-agent-worker.mjs` | One real Antigravity delegation, about two cents. The only cheap way to confirm entitlement, region, and credential liveness. |

## Install and prerequisites

| Symptom | Cause | Fix |
|---|---|---|
| `codex: command not found` | Global npm bin not on `PATH`. | `npm install -g @openai/codex`, or add the output of `npm root -g`'s `../bin` to `PATH`. |
| `Node <n> — this repo needs Node 20 or newer` | Older Node on `PATH`. | `nvm install --lts`, or install from [nodejs.org](https://nodejs.org). |
| `verify-setup.mjs`: `mcp-dependencies` or `mcp-build` (blocking) | `dist/` and `node_modules/` are not tracked in git; a fresh checkout carries source only. | Re-run with `--fix` — runs `npm ci` then `npm run build` in the server directory. |
| `verify-setup.mjs`: `skills-discoverable` (warning), listing every skill | Codex scans `.agents/skills`, not `plugin/skills/` where they ship. Only affects the clone route. | `node plugin/codex/verify-setup.mjs --fix` links them once. Installed as a plugin, ignore this — codex loads skills from the manifest and the check is looking in the wrong place. |
| `$mmo-codex:*` skills are not offered in a codex session | The plugin is not installed, or is disabled. | `codex plugin list`. If absent, `codex plugin marketplace add <repo-or-path>` then `codex plugin add mmo-codex@tilicho-ai-labs`. |
| Skills changed on disk but codex runs the old version | A session runs the copy in `~/.codex/plugins/cache/`, made at `codex plugin add`, whichever marketplace it came from. | Git marketplace: `codex plugin marketplace upgrade`, then `codex plugin add mmo-codex@tilicho-ai-labs`. Local path: `codex plugin add mmo-codex@tilicho-ai-labs` again. See [CONTRIBUTING.md](../CONTRIBUTING.md#test-a-branch-in-a-codex-session) to run a branch. |
| `verify-setup.mjs`: `mcp-build-stale` (warning), or `the dispatch bridge's build is older than its source` from `run.mjs` or `start-run.mjs` | A pull or an edit changed `plugin/mcp/model-dispatch/src/` after the last build, so every dispatch runs the old bridge. | `node plugin/codex/verify-setup.mjs --fix` rebuilds it. On a local-path install, run `codex plugin add mmo-codex@tilicho-ai-labs` afterwards so the session's copy gets the build. |

## Login and credentials

| Symptom | Cause | Fix |
|---|---|---|
| `codex is not logged in` while `codex login status` says otherwise | Fixed. Older builds of this check read stdout only, and codex 0.152.x prints login status to stderr. | Update this harness. The check now reads both streams. |
| `OPENAI_API_KEY is not set, and … routes judgment work through the metered openai adapter` | The selected policy bills the key, and it is not set. | Export a key, **or** switch to a policy that needs none: `node plugin/scripts/setup-policy.mjs --policy=gpt-seat-plus-flash --project-root "$(pwd)"`. See [running.md](running.md#policies). |
| `--check-creds` reports `GEMINI_API_KEY` missing on a machine where Gemini works | Fixed. That key is the AI Studio door to a tier Google Cloud application-default credentials also open; an older check treated it as mandatory. | Update this harness. The key is now reported only when both doors are shut. Do not buy an API key for a tier your ADC is already serving. |
| `gemini-credentials-broken` (blocking) | A Google credential is configured but no auth library can load it — most often a service-account file with no `private_key`. | Point `GOOGLE_APPLICATION_CREDENTIALS` at a complete key, or unset it and run `gcloud auth application-default login`. An explicit `GOOGLE_APPLICATION_CREDENTIALS` takes precedence over the gcloud file, so a broken one hides a working login. |
| `gemini-credentials` (warning) with `GOOGLE_CLOUD_PROJECT` set | A project ID says where to bill, not who is asking. | Fine on a Google-hosted machine, where the credential comes from the metadata server. Anywhere else, run `gcloud auth application-default login`. |

## Dispatch and the bridge

| Symptom | Cause | Fix |
|---|---|---|
| `MCP error -32000: Connection closed` | Codex's sandbox permits child processes but denies the pipes needed to talk to one, and the bridge is reached over exactly those pipes. The server is not crashed, missing, or unbuilt. | Start codex with `codex -s danger-full-access`, or run the pipeline from a plain shell with `node plugin/codex/run.mjs`. Both the default and `workspace-write` sandbox modes fail this way. |
| `this run requires auth_mode=vendor\|estimated` | `preflight_dispatch` was called without `auth_mode`. Pre-flight cannot tell which models a run dispatches to without it. | The flag belongs to the dispatcher, not the driver: `node plugin/codex/dispatch.mjs --preflight --auth-mode=vendor`. Every call in this harness is dispatched, so `vendor` is the only correct value — see [plugin/skills/pipeline/SKILL.md](../plugin/skills/pipeline/SKILL.md). `run.mjs` has no `--auth` flag, and exits 2 on any flag it does not know. |
| `MCP error -32001: Request timed out` at 60 seconds | An MCP client using the SDK default rather than this harness's 900-second timeout. A real dispatch at effort `high` takes far longer. | Use `connectBridge` from `plugin/mcp/model-dispatch/dist/driverClient.js`, which sets the timeout explicitly. |
| A dispatch fails immediately with an adapter construction error | The policy names an adapter whose credential is absent — most often `openai` with no `OPENAI_API_KEY`. | `node plugin/scripts/setup-policy.mjs --check-creds --policy=<name>` names what is missing. |
| `dispatch: --telemetry=<path> is required for --packet` | A dispatch named no telemetry file. A paid call with no telemetry line is spend no report or cost cap can see, so `dispatch.mjs` refuses before it starts the bridge. | Pass the run's file: `--telemetry='<output-dir>/telemetry.jsonl'`. The brownfield pre-check's dispatch smoke uses `.sdlc/pre-check/telemetry.jsonl`: it checks the project, its result is cached for later runs, and its cost stays out of every run's total and cost cap. |
| `TaskPacket.phase '<name>' is not a phase the bridge routes` (or `log_telemetry: event.phase …`) | The packet, or a `--log-phase` record, carries a state-machine step name such as `execute_packets` or `test_run`. No policy rule matches one, so it would route to the default tier and get no report row. | Use a phase from the message: step 5's packets are `codegen`, `tests` or `docs`, and a step 7 failure is `debug`. |
| `dispatch: the model call failed (terminal_reason=…)`, exit 1 | The bridge ran the call and the model returned `success: false`. | Read the `--out` file, which is still written: `result.error` and `terminal_reason` say what failed. The failed attempt is already in telemetry. |
| `api.codex_cli.stream_warning` in the log | A nested `codex exec` reconnected or warned mid-turn (`Reconnecting... 1/5`, `Model metadata for … not found`). | Nothing to fix. A `codex-cli` dispatch fails only on `turn.failed`, on an error with no completed turn, or on a non-zero exit with no turn; this one succeeded and is billed on its turn's usage. |
| `dispatch deadline of <n>s reached (the leaf's worker_timeout_sec)` | A Gemini or OpenAI dispatch, its output-cap doublings and resent requests included, ran past its leaf's `worker_timeout_sec` (840 s when unset). | Raise `worker_timeout_sec` on that policy leaf, keeping it under 870 s (the driver client waits 900 s), or split the packet. |
| `dispatch.abandoned` in the log, and a telemetry row whose `error` starts `abandoned` | The client stopped waiting while an attempt was in flight: its call timeout, a closed connection, or a signal. | The attempts that finished first are in telemetry at their real cost. The abandoned one is a lower bound (`usage_complete: false`); the vendor request was cancelled, and any nested `codex` or agent worker was killed with its whole process group. |

## Running

| Symptom | Cause | Fix |
|---|---|---|
| A `run.mjs` run ends with `max_turns — --max-turns=12 reached before the run finished` (exit 3) | One `codex exec` turn ends at its context ceiling with exit 0 and no error, so the driver resumes; this run used every invocation `--max-turns` allows before Gate 4. | Run the `Continue:` command it printed, `--resume=<run-id>`; add `--max-turns=24` for a large brief. Each driver process gets its own `--max-turns`. See [running.md](running.md#resuming-a-partial-run). |
| `run <id> already has a record at <dir>; continue it with --resume=<id>, or choose a new --run-id.` (exit 2) | A fresh run named a folder that holds another run's record. Nothing is overwritten. | Continue that run with `--resume=<id>`, or drop `--run-id` for a new folder. |
| `--output-dir=.sdlc is the folder every run shares. Drop --output-dir; …` (exit 2) | A command from an older doc. Each run keeps its record in `.sdlc/runs/<run-id>/`. | Drop `--output-dir`. |
| `<root> is not a git repository. For a new app in an empty folder pass --mode=greenfield; …` (exit 2) | `run.mjs` was started without `--mode=greenfield` in a folder with no git. A brownfield run needs git. | Pass `--mode=greenfield` for a new app, or `git init` and commit for brownfield. |
| `<folder> is inside the git project at <root>, not its root. …` (exit 2) | A brownfield `run.mjs` run, or one with no `--mode`, was pointed at a subfolder of a repository. Its write contract is frozen at Gate 0 at the repository's root, the only place the write hook reads it. Nothing was spent. | Pass the root the message names as `--project-root`; Gate 0's allowlist can still keep the run's writes to the subfolder. For a new app in that subfolder, pass `--mode=greenfield`. |
| A brownfield run asks nothing about the job type | Expected when invoked through one of the seven aliases — `$mmo-codex:refactor` and friends hand over the intent pre-selected. | Use `$mmo-codex:brownfield` for the seven-option menu. |
| `--gates=prompt needs a person at this terminal, and stdin is not one.` (exit 2) | `prompt` is the default gate mode, and the run was started from CI, a pipe or another program. Nothing was spent. | `--gates=auto-approve` for a replay of a reviewed run, or `--gates=auto-abort` to stop at the first gate. |
| Brownfield in a session stops right after Gate 0 with `The write guard did not run in this session` | Codex skips a plugin hook nobody trusted yet, or one whose entry changed in an update, and says nothing. The run is ended and its contract switched off. | Start codex and choose "Trust all and continue" when it asks about hooks, or open `/hooks` and trust mmo-codex's `PreToolUse` hook. Then start the job again. |
| `COST_CAP_EXCEEDED: $<n> is already recorded for this run, at or above hard_cost_cap_usd $<cap>` | The run's dispatched cost plus the conductor's modeled cost reached the policy's cap. The message gives both parts. | The run stops (exit 4 under `run.mjs`). To go on, raise `hard_cost_cap_usd`. A run on a project's `routing-policy.yaml` resumes on the edited file, with a warning that it changed. A resume refuses a different policy file, so a run on a shipped policy goes on as a new run, with a `routing-policy.yaml` of your own at the project root. |
| `pricing.policy_mismatch` in the log | A policy's `pricing:` block differs from the dated price list by more than 0.5%. Without `pricing_override: true` the block is documentation, so the list is billed. | Nothing to fix for the bill. Bring the block in line with `plugin/mcp/model-dispatch/src/prices.ts` to silence it. |
| Gemini dispatches cost twice as much from 2027-01-01 | Gemini 3.7 and 3.8 Flash's introductory card ends 2026-12-31; the price list bills 1.50 / 0.15 / 7.50 per 1M from 2027-01-01. | Expected. Each event is priced on its dispatch's UTC day. |
| `unpriced: …` from a dispatch, or `preflight_dispatch` halts on a model | The dated price list (`plugin/mcp/model-dispatch/src/prices.ts`) has no entry for that model on that day. The dispatch is refused before any vendor call, at $0. | Use a shipped policy, or set `pricing_override: true` with a `pricing:` block on that model in your own policy. |
| The run's end prints `driver usage: not collected (…)` | The conductor's codex session file was not found or could not be read, so `driver-usage.json` was not written. | Check that `CODEX_HOME` is the folder codex wrote the session to, then run `node plugin/scripts/collect-driver-usage.mjs .sdlc/runs/<run-id>` and render the report again. |
| The driver's `Cost source` reads `INCOMPLETE: this run's turns in 1 conductor thread(s) left out, as run.json records no start of this run there` | The run went on in a codex chat that `start-run.mjs` never ran in, such as one opened with `/new` and told to carry on, or to close the run out, without `--resume`. Its dispatch or end-of-run markers name that chat, and the figure leaves its turns out. The `Left out` line names the thread. | Count it with `node plugin/scripts/collect-driver-usage.mjs .sdlc/runs/<run-id> --thread=<thread-id>`, where `<thread-id>` is the id the `Left out` line names, then render the report again. |
| The report reads `Driver loop — modeled` … `Not measured`, and the run total `not measured` | The run folder has neither `driver-cost-modeled.jsonl` nor `driver-usage.json`. | Collect the conductor's usage as in the row above. |
| A write the model attempted did not happen, with no error in the transcript | The write-contract hook refused it as out of scope. A denied call leaves no trace in the Codex event stream. | Read `.sdlc/local/guard-decisions.jsonl`. While a contract binds, every decision is recorded there with its reason; outside a run, a refusal is recorded only when the project already has `.sdlc/`. |
| A write is refused with `… is in run <new-id>'s folder, but run <id> still holds this project's write contract`, or `$mmo-codex:brownfield` reports a run that `still holds the write contract` | A brownfield run that never reached close-out, such as a killed session, leaves its lock live, and its contract binds every Codex session in the repository. | If that run is over, end it: `node plugin/scripts/write-contract.mjs --abandon --run-id=<id> --project-root=<repo>`, where `<id>` is the run the message names and `<repo>` is the repository's root. Answering `discard` at `$mmo-codex:brownfield`'s first step runs the same command. |
| Every write in the repository is refused with `the write contract changed after run <id> froze it` | Something rewrote `.sdlc/local/write-contract.json` while its run was live. | Find what changed it, then end the run with the `--abandon` command above. |
| A brownfield `run.mjs` run exits 2 with `run <id> is live and holds this project's write contract, so this run's Gate 0 freeze would be refused` | Another run's contract still binds the repository. Nothing was spent. | Resume that run with `--resume=<id>`, or end it with the `--abandon` command the message prints. |
| A `run.mjs` run ends with `driver model: codex's session file says thread <id> ran <model> at effort <effort>, not the pin …` | Codex answered on another model or effort than the `-m` and `model_reasoning_effort` the driver passed. `driver-manifest.json` `driver_model_observed` records it per thread. | Check `~/.codex/config.toml` and any profile for a model override, and the codex version. The exec-stream driver cost assumes the pin, and the session-file figure lists those turns as unpriced. |
| The driver's `Unpriced` line reads `<model> (<n> turns; session model <model> is not the pin gpt-5.6-terra)`, `Cost source` includes `INCOMPLETE: unpriced tokens excluded`, and the run total reads `at least` | `/model` switched the run's codex session to another model mid-run. The session-model check runs at run start and on resume only, so the run went on, and its turns on the other model are listed as unpriced, not priced at the pin. They add nothing to the cost cap either. | Keep the session on `gpt-5.6-terra` at effort `high` until the run ends; to change model, start a new codex session. This run's conductor figure stays a floor. |
| `plan-packets: the plan in <result> was refused (attempt <n> of 3). Nothing was written.`, then a numbered list | The Phase 4 planner returned a plan that breaks the plan schema or this run's scope: a phase or task type the plan does not take, a target outside the frozen allowlist or off-limits, an input that names an off-limits file or gives a slice of a file a packet rewrites, a child `output_schema_json` that does not parse to a JSON Schema. `packets.json` is not written. | Nothing to do by hand. The conductor builds the next planner packet with `--previous=<result>`, which hands the list to the planner. |
| A run stops at Phase 4: `stop.json` says `the planner returned no plan that passes plan-packets.mjs in 3 attempts` | Three plans in one session were refused. | Print the last refusal with the `--accept` command `needs` names. A target the job needs outside the frozen allowlist is a new run, whose Gate 0 confirms the wider scope. Otherwise edit `<run folder>/plan-instruction.md` if you want to steer the plan (the files each packet changes, the design sections), and resume with `--resume=<run-id>`: the conductor plans again from that file, with three new attempts. |
| A run stops at Phase 4: `stop.json` says `the plan dispatch failed 2 times` | The planner's model sent no reply, twice: a codex-cli timeout, a ChatGPT seat's usage limit, an API error after the adapter's retries, or a strict-mode refusal. The error is in `reason` and `needs`. Neither dispatch counts as an attempt. | Fix what the error names, then resume with `--resume=<run-id>`. |
| `--resume` exits 2 with `run <id> ended aborted, so it does not resume` | The run was aborted at a gate or abandoned. Its scope was confirmed for that run only. | Start a new run; its Gate 0 confirms the scope again. |

## Policy

| Symptom | Cause | Fix |
|---|---|---|
| `policy '<name>' not found` | Typo, or a policy that was never shipped. | `node plugin/scripts/setup-policy.mjs --list-json` prints every policy this install can see. |
| `--policy=opus-plus-flash` (or another `opus-*` name) fails with `Policy '<name>' not found` | The Claude harness's policies do not ship with this plugin. | Pick one of `gpt-plus-flash`, `gpt-plus-flash-38`, `gpt-seat-plus-flash`, or `flash-agsdk-only`. |
| `run: policy '<name>' (…) names an Anthropic adapter (…), and this harness runs no Anthropic model` (exit 2) | The policy that won, usually a `routing-policy.yaml`, routes a model through `builtin-anthropic` or `claude-cli`. Nothing was spent. | Route those phases through `openai`, `codex-cli`, `mcp:model-dispatch` or `antigravity-worker`, or move the file aside and pick a shipped policy. |
| `run: policy '<name>' (…) pins the conductor to '<model>', which is not a GPT model` (exit 2), or the same from `setup-policy:` (exit 1), which also refuses a `driver:` block with no `model_name` | The policy's `driver:` block names a model that is not GPT, and this harness runs its conductor in codex on a GPT model only. Nothing was spent, and setup writes no `default_policy`. | Under `driver:`, set `model_name: gpt-5.6-terra` and `reasoning: { effort: high }`, as every shipped policy does. |
| `<root>/.sdlc/project.json is not valid JSON … Fix or delete the file.` (exit 2), or `project-json-invalid` (blocking) from `verify-setup.mjs` | A run started without `--policy` reads `default_policy` from that file, and the file does not parse, or `default_policy` is not a string. | Fix the JSON by hand; the file can hold other project settings, so read it before you delete it. To start over, delete it and pick a policy again: `node plugin/scripts/setup-policy.mjs --policy=gpt-plus-flash --project-root "$(pwd)"`. |
| `Policy name '{{POLICY}}' (…) is not a policy name … It is an unrendered {{PLACEHOLDER}}` | A command was copied from a skill file whose `{{POLICY}}` was never filled in, or `default_policy` in `.sdlc/project.json` holds that literal text. | Pass a real name, for example `--policy=gpt-plus-flash`. If `default_policy` holds the placeholder, set it again: `node plugin/scripts/setup-policy.mjs --policy=gpt-plus-flash --project-root "$(pwd)"`. |
| `Policy model '<id>': unknown adapter '<x>'` | The policy names an adapter no code implements, usually a typo. Caught at load, before any dispatch. | Use one of the known adapters the message lists. |
| `run: <root>/routing-policy.yaml (policy '<name>') is used instead of --policy=<name>` | A project's `routing-policy.yaml` beats `--policy`. | Expected. Move or rename the file to run a shipped policy. |
| `fairness pin: policy '<name>' has no driver: block` | A policy of your own with no `driver:` block and no `gpt` model entry to fall back on. | Add the `driver:` block the message prints, at the top level. |
| `run: --resume refused: the policy name differs` (or file, or driver pin) | The resumed invocation resolves a different policy than the one the run started on. | Resume with the same `--policy` and the same `routing-policy.yaml`, or start a new run. |
| `start-run: no run started: this session must run gpt-5.6-terra at effort high.` then `session model check: this session runs <model> …` (exit 1) | The codex session runs a different model or effort than the driver pin. A turn with no effort set runs the model's default level (`medium` for `gpt-5.6-terra`), which is not the pin. `start-run.mjs` starts no run and creates no run folder. | `/model` in the session, choose `gpt-5.6-terra` and effort `high`, send one message, then start the skill again. Or start codex with `codex -s danger-full-access -m gpt-5.6-terra -c model_reasoning_effort="high"`. |
| `start-run: no run started: …` then `session model check: unverified (…)` (exit 1) | The session's rollout file under `$CODEX_HOME/sessions/` could not be read, or `CODEX_THREAD_ID` is not set because the command was not run by codex. The run stops rather than price the driver at a model it cannot confirm. | Start the skill from a codex session. Check `/status`, and that `CODEX_HOME` points at the folder codex writes its sessions to. |
| Cost figures for a run are lower than expected, or absent for the judgment tier | The run used `gpt-seat-plus-flash`, where judgment cost is modeled from token counts rather than metered. | Expected. `M` marks those rows in the report, and they are kept out of the vendor total. Use `gpt-plus-flash` for figures that get published. See [methodology.md](methodology.md). |

## Agent path (Antigravity SDK)

| Symptom | Cause | Fix |
|---|---|---|
| `agent-worker-python` (blocking) | The mechanical tier is routed to the agent worker, which has no Python environment. | `node plugin/codex/verify-setup.mjs --fix` builds it. Or set `GEMINI_WORKER_PYTHON` to a Python 3.10+ that already has `google-antigravity`. To go back to the model path, `--disable-agent`. |
| `agent-worker-sdk` (blocking) | The environment exists but cannot import `google.antigravity` — usually built against an interpreter since upgraded or removed. | `--fix` rebuilds it from scratch. |
| `agent-worker-credentials` (blocking) with `GEMINI_API_KEY` set | The agent path reaches Gemini through Vertex and application-default credentials only. There is no API-key door for it. | `gcloud auth application-default login`, plus `GOOGLE_CLOUD_PROJECT` if the account has several projects. |
| Every delegated task fails to authenticate after the judgment phases already billed | A credential that exists but carries no entitlement to the pinned model in that region. Offline checks cannot see this. | `node plugin/scripts/probe-agent-worker.mjs` settles it for about two cents, before a real run. Run it from the project root, or pass `--telemetry=<path>`: it records that spend at `--telemetry` when given, else in `.sdlc/pre-check/telemetry.jsonl` when the project root (`--project-root`, the working directory by default) has a `.sdlc/`, else in `telemetry.jsonl` in its temporary evidence folder, where no report or cost cap reads it. |
| `agent-worker-sdk-version` (warning) | The worker environment holds a `google-antigravity` version other than the pinned 0.1.16. The SDK changed what its usage totals mean between releases. | `node plugin/codex/verify-setup.mjs --fix` rebuilds the environment from `requirements.txt`. Editing the file does not change an environment that is already built. With `GEMINI_WORKER_PYTHON` set, `--fix` does not touch that interpreter: run `"$GEMINI_WORKER_PYTHON" -m pip install google-antigravity==0.1.16`, or unset the variable before `--fix`. |
| `agsdk.usage_semantics_unverified` in the log | A delegation's sidecar records an SDK version that is not in `AGY_USAGE_SEMANTICS`. | Its input was billed on the larger reading, so its cost can be high but not low. Rebuild the environment with `--fix`. With `GEMINI_WORKER_PYTHON` set, run `"$GEMINI_WORKER_PYTHON" -m pip install google-antigravity==0.1.16` instead, or unset the variable before `--fix`. |
| `agsdk.usage_missing` in the log, and a delegation with `usage_complete: false` | The agent session ran but no usage survived: it was killed at its deadline, or the SDK's totals could not be read. | The cost is a lower bound, the brief as input. Raise `worker_timeout_sec` on the leaf if the task needs longer. |

## Repair after a plugin update

A plugin update replaces the source and removes the build, so the bridge has no `dist/` until it is rebuilt:

```bash
node plugin/codex/verify-setup.mjs --fix
```

`$mmo-codex:setup` does the same from inside a session. Both are idempotent — safe to run at any time, and a no-op when nothing needs doing.
